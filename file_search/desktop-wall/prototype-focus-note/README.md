# PROTOTYPE — 只顯示單一便利貼：兩種架構草稿

**throwaway，不是正式功能**——用完做完決定就整包丟到分支保存，不留在 main。

## 要回答的問題

「只顯示這則便利貼（其他都消失）」要用哪種底層架構：

- **🅰 牆本身視窗裁切**——直接把 desktop-wall 的牆視窗本身縮小/搬移成剛好貼合
  使用者拖框選出的範圍，其他內容裁掉，退出時視窗變回原尺寸。
- **🅱 獨立懸浮視窗**——另外開一個跟叉叉按鈕同一套機制的小視窗，只放這則便利貼，
  可拖曳移動，牆本身維持原樣（來源那則在牆上先隱藏，關掉懸浮視窗才恢復）。

第一版 🅰 原本是「按鈕點某一則、精確裁到那一則的大小」；改成**在空白處拖拉框選**
之後：選取範圍不綁定任何一則便利貼的大小，可以一次框住好幾則一起裁切，裁切的
做法也從「CSS 藏起其他內容」改成「視窗本身縮小/搬移到框選範圍 + `#board`
用 CSS transform 位移，讓框選範圍左上角對齊新視窗座標系統」，是真的讓視窗只
顯示那塊區域，不是模擬出來的。

兩者現在比較像是**解決不同問題**，不是單純二選一：🅰 是「畫面太亂，先把這一小
塊留著看」（單一視窗，一次一個檢視範圍，但範圍內可以有好幾則），🅱 是「把某一則
單獨拉出來，之後可以放到螢幕任何地方、跟其他東西並存」（每則各自一個視窗，
天生支援同時好幾個）。拖曳這件事現在兩邊都用上，且意義不同：🅰 是拖出一個
「要看的範圍」，🅱 是把便利貼整張拖到視窗邊緣放開＝直接彈出成懸浮視窗
（不用先點按鈕）。

**🅱 有一個已知簡化，寫在 `wall.html` 的註解裡**：Chromium 的 `mousemove` 一旦
游標離開視窗範圍就不會再送進來，這是瀏覽器層級的限制，所以這裡拿「拖到離視窗
邊緣一小段距離內」當觸發點，不是真的追蹤到牆外的座標。體感上很接近「拖出牆
外」，但不是 Chrome 分頁拖出變新視窗那種真正無縫的連續手勢——那個需要主行程
另外用 `screen.getCursorScreenPoint()` 搭配全域滑鼠鍵狀態偵測持續輪詢，是更大
一塊工程，先確認這個簡化版的手感對不對再決定要不要做到那麼細。

## 執行方式

雙擊 `run.bat`（借用 desktop-wall 已經裝好的 electron，不用另外 npm install）。

視窗裡有 4 張假便利貼：

- **🅰 在空白處按住拖拉**：放開後畫出的框選範圍會變成新的視窗大小/位置，
  框到幾則就看到幾則，其他全部裁掉；畫面下方「⬅ 恢復完整畫面」可以退出、
  再拉一次新的框。
- **🅱 直接拖便利貼本身到視窗邊緣放開**：靠近邊緣時邊框會亮紅提示「放開就會
  彈出去」，放開後原地開一個小懸浮視窗顯示那則，可以直接拖曳移動位置，牆上
  原本那則會暫時消失；懸浮視窗按右上角 ✕ 關掉，牆上那則就恢復。可以對好幾則
  各自拖出去，會看到好幾個懸浮視窗同時存在。拖了但沒拖到邊緣就放開＝取消，
  便利貼彈回原位。

## 檔案

```
main.js          Electron 主行程：建牆視窗、處理裁切/懸浮兩種 IPC
wall-preload.js  牆視窗的 IPC 橋
wall.html        假牆面 + 4 則假便利貼 + 🅰🅱 按鈕邏輯
float-note.html  懸浮視窗顯示的內容（不需要 preload，window.close() 是原生 API）
run.bat          雙擊執行
```

## 決定之後

留意兩件事再定案：

1. **DPI／多螢幕**：這裡量座標直接用 `getBoundingClientRect()` + `BrowserWindow.getBounds()`
   相加，沒處理縮放比例不是 100% 或跨螢幕拖曳的情況，正式做需要補。
2. 如果選 🅱，牆上原本那則要不要真的隱藏（這裡的做法），還是留著但變成某種
   「已釘選」的視覺提示（半透明／打勾）——這個留到正式設計時再定。
