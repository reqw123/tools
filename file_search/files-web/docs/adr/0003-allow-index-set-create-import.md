# 放寬範圍：允許「索引集層級」的匯入（建立）與匯出

`0001` 把「索引集本身的建立／刪除（.md 檔）」明確劃給桌面版；`0002` 放寬到
「索引項目層級」的增刪，但維持索引集本身的建立/刪除仍是桌面版職責。使用者
後來要求比照桌面版新增的「📥 匯入索引集」「📤 匯出索引集」按鈕，這份 ADR
再放寬一格範圍，加入**索引集層級的匯入（=建立一份新的 .md）**：

- **匯出**：把目前選取索引集的原始 `.md` 內容（`IndexPayload.raw`，本來就已經
  抓在前端）存到使用者指定的位置。純讀取，不需要新的後端邏輯，只是把既有的
  `raw` 包成 Blob 觸發瀏覽器下載（`lib/exportIndex.ts`）。
- **匯入**：選一份既有的 `.md`（本機檔案，透過瀏覽器 `<input type="file">`
  讀取內容，不經過伺服器的檔案系統瀏覽——來源可能不在 `indexDir` 底下）→
  取名（預設帶入來源檔名）→ 送到 `POST /indexes/import`，存成一份新的索引集。
  `server/store.ts` 新增 `validateIndexName()` / `createIndexFile()`，對齊桌面版
  `IndexRepository.validate_name()` / `import_index_file()` 的規則（不合法字元、
  空名稱、撞名）。前端 `ImportIndexDialog` 也做了同一套規則的即時驗證，
  伺服器端仍是最後一道防線（多分頁/多行程同時建立時，前端手上的清單可能過期）。

**仍然不做**（`0001`/`0002` 的範圍決定維持）：改**路徑**（要換路徑＝移除再重加）、
前言（preamble）prose 的編輯、索引集的**刪除**、AI 全文搜尋、全文快取、重複偵測、
音訊／影片轉錄。

## 後果

- `store.ts` 多了 `validateIndexName()` / `createIndexFile()`，跟桌面版
  `IndexRepository` 的對應函式又多一份 TS 移植——索引集命名規則（不合法字元、
  `.md` 補全、撞名判斷）若變動，兩邊都要改。
- 匯入內容不驗證表格格式是否正確——不合法的列 `readIndex()` 本來就會安靜跳過
  （計進 `skipped`），不會讓匯入整個失敗，這點跟項目層級的匯入（`0002`）一致。
- 匯入的來源檔案不需要在這台機器的 `indexDir` 底下（甚至不需要在同一個磁碟機），
  因為讀取是瀏覽器端的 `File.text()`，不是後端檔案系統操作——跟「加入索引」
  選檔（`FileBrowser`，伺服器端瀏覽 `indexDir` 以外的任意路徑）是不同的路徑。
- 跟桌面版一樣，這裡新增的「匯入索引集」JSON/檔名驗證邏輯不會影響
  `0002` 已經放寬的項目層級操作（新增/編輯/刪除/批次），純粹是額外加一種
  索引集層級的寫入能力。
